# Berry web chat

This is a separate browser entry point for cloud chat. It does not load Electron or local inference.

Set `BERRY_WEB_PASSWORD` and a provider source before starting. To reuse Berry Studio's saved custom OpenAI-compatible providers, set `BERRY_WEB_PROVIDER_DB` to the absolute path of its `Data/cherrystudio.sqlite`. The web server opens that database read-only, uses enabled providers, models, and keys, and never sends keys to the browser. It also uses the first active, trusted Streamable HTTP MCP server and its saved headers. Set `BERRY_WEB_MCP_NAME=comfyui-concurrent` to select that active saved connection explicitly for the web app; this does not change the desktop setting. Alternatively, set `BERRY_WEB_PROVIDER_KEY` and `BERRY_WEB_MODEL` (`BERRY_WEB_PROVIDER_URL` defaults to OpenAI's API). Set `BERRY_WEB_MCP_URL` to override the saved MCP server. Tool calls require confirmation in the browser. Images up to 10 MB can be uploaded in chat; MCP image results are stored and displayed. Conversations and images are stored in `berry-web.sqlite` by default; set `BERRY_WEB_DATABASE` to move it.

Run `pnpm web:dev` and open `http://localhost:4174`. The server listens on loopback by default; `BERRY_WEB_HOST` changes the bind address for a controlled LAN test. `BERRY_WEB_PROVIDERS` can supply a JSON array of `{id,name,url,key,model}` for multiple hosted models. Saved-provider reuse works only where the desktop profile is available; a remote backend needs its own provider configuration. This local prototype accepts one MCP endpoint. Do not expose the development server to the internet; deployment needs TLS, durable sessions, and an external authentication layer.
